# ウェルカム画面・貢いだ金額・デザインの見直し（設計）

2026-10-29。推し馬ノート（Android、`com.tktkcompany.kakoRaceKeiba`）。会話で作者と決めたことをまとめる。
「作者の判断」と書いていないものは、作者が決めたこと。「私の判断」は設計者（Claude）が決めたことで、作者が読んで直してよい。

## なぜやるのか

作者の言葉：「推し馬を作ってコレクションして楽しんでほしい」。
今のアプリは、初めて開くとホームに「推し馬を登録しよう」という案内が出るだけで、
「推し馬を集めて、飾って、応援するのが楽しいアプリ」だということが伝わらない。
また、ボタンや色が古く、ばらばら（緑の帯・オレンジの文字・青のリンク・赤いログアウト）で、作者は「モダンな感じ」にしたい。

成功のめやす：初めて入れた人が、ウェルカム画面を見て「推し馬を集めるのが楽しそう」と感じ、そのまま推し馬を登録したくなること。
アプリ全体が、新しいアイコン（金色の馬の顔）と同じ「金色とクリーム」の、かわいくてまとまった見た目になること。

## 3つの部分

1. ウェルカム画面（初めて入れたときに1回だけ）
2. 貢いだ金額・回収した金額と、称号のバッジ（新しい機能）
3. アプリ全体のデザインの見直し（金色とクリームの色、Material 3 の形）

**3つまとめて、1つのバージョン（394）で出す**（作者）。3 は 1・2 の土台（色・ボタンの形）になるので、3 → 1 → 2 の順に作る（私の判断）。

## 1. ウェルカム画面

- アプリを入れて**初めて開いたときに1回だけ**、ホームの前に出す。2回目以降は出さない。
- 目的は**楽しさを伝えるだけ**。この画面の中で推し馬の登録はさせない（作者）。閉じるとホームに行く。
- **かわいい感じ**。色は「金色とクリーム」（クリーム `#FFFBEA` → 金 `#F7C255` のグラデーション、文字は濃い茶色 `#5A3A1A`、強調は `#C46A00`）。ストア画像（`store/make-store-images.js`）と同じ色。
- キャラクター：**今のアイコンの茶色い馬の顔に、白い羽を両側に足した「ペガサス」**（作者が3案から「1」を選んだ）。ウェルカム画面の中だけで使う。**アプリのアイコンは変えない**（作者）。
  - 絵の元：`store/icon/make-icon.js` の顔の部品。羽のたたき台は `.superpowers/brainstorm/776-1793283226/content/welcome-flow.html` の `#wing`（ベクターで描ける）。
- 左右にスワイプする**3枚**。どの画面でも右上の「スキップ」で飛ばせる（3枚目にはスキップなし）。下に今の位置を示す点。
  1. 「ようこそ、推し馬ノートへ！」／「あなたの『推し』の馬を見つけて、応援しよう」。羽のある子を大きく。ボタン「つぎへ」
  2. 「カードを飾って、コレクション」／「アイコンと背景を選んで、推し馬ごとに自分だけのカードに」。飾ったカード3枚を扇形に、羽の子を小さく。ボタン「つぎへ」。**貢いだ金額の称号バッジも、カードの絵に入れて見せる**（2 の機能を伝えるため）
  3. 「走る日も、結果もお知らせ」／「出番を見逃さないから、応援がもっと楽しくなる」。お知らせの吹き出し3つ（出走決定・発走30分前・1着）。ボタン「はじめる」
- 文面と絵は、たたき台（`welcome-flow.html`）で作者が「伝わると思う」とした。細かな言い回しは作る人が整えてよい。英語の文も用意する（アプリは英語にも対応している。`Lang.t` か `values/strings.xml`）。
- カードの馬の名前は**作りもの**（サクラノユメ、キンイロダイヤ、ソラノカケラ）。実在の馬は使わない。
- **通知の許可**：今は `MainActivity.requestNotificationPermissionIfNeeded()` が起動してすぐ聞いている。ウェルカム画面を出すときは、**3枚目の「はじめる」を押した（またはスキップした）あとに聞く**ように変える（私の判断。お知らせの楽しさを見せた直後のほうが許可されやすい）。2回目以降の起動は今のまま。
- 今アプリを使っている人（アップデートで入る人）には出さない（私の判断。初めての人のための画面なので）。見分け方は作る人に任せる（例：推し馬がすでにいる、または前のバージョンから上がった）。

## 2. 貢いだ金額・回収した金額と称号

今のアプリには、買い目を記録する機能がある（`ui/prediction/Bets.java`。Firebase の `users/{uid}/bets/{開催日}/{id}` に `course, raceNo, title, type, numbers, amount, payout`）。記録だけで、馬券は買わない。ゲストも自動でログインしているので、全員が使える。

- **貢いだ金額**：その推し馬が**入っている**買い目の `amount` を、すべて足す。単勝・複勝だけでなく、馬連・3連単などの組み合わせでも、推し馬が1頭として入っていれば**まるごと**数える（作者）。
- **回収した金額**：同じ買い目の `payout` をすべて足す。組み合わせで当たったときも**まるごと**（私の判断。貢いだ金額と同じ数え方にそろえる）。結果がまだのもの（`payout == null`）は、貢いだ金額には入れ、回収には入れない（私の判断）。
- **期間は通算**（私の判断）。
- 買い目は**馬番**（枠連だけは枠番）で記録されているので、そのレースの出走表で馬番を馬に置きかえて、推し馬かどうかを決める。馬の見分けは、推し馬の保存に使っている名前と同じやり方で（作る人が既存のコードに合わせる）。出走表が取れないレースの買い目は数えない。
- **枠連**は `numbers` が枠番（1つの枠に2〜3頭）。その枠に推し馬が入っていれば、まるごと数える（私の判断。「まるごと」にそろえる）。そのため、出走表から各馬の枠番も使う。
- **払戻がまだ書かれていない買い目**：今は `Bets.settle()` が、そのレースの画面を開いたときだけ `payout` を書く。開いていない過去のレースは `payout == null` のままで、回収が少なく出てしまう。数えるときに、結果が出ているはずの過去のレースで `payout == null` のものは、`LivePayouts` で払戻を取って `settle` と同じように Firebase に書き戻す（私の判断）。取るのはまだ書かれていないレースだけで、1回書けば次からは取らない。取れなかったら、そのまま（回収に入れない）。
- 過去のレースの馬番・馬名は `race_entries` のほか `race_results` にもあるので、出走表が取れないときはそちらを使ってよい。
- 出す場所（作者：「どっちも」）：
  - **推し馬のカード**（ホームの主役のカード、横に並ぶカード、推し馬の一覧）：「貢いだ 23,000円／回収 8,400円」を小さく。買い目が0件の馬は出さない（私の判断）。
  - **馬カルテ**（`ui/horse/HorseFragment`）：合計と、レースごとの内訳（日付・レース・券種と買い目・金額・払戻）。
- **称号のバッジ**（作者：A「選んだアイコンはそのまま＋称号のバッジ」。アイコンは勝手に変えない）。カードの右上に、白い丸いバッジで「絵文字＋称号」。
  | 称号 | 貢いだ金額 |
  |---|---|
  | 🌱 はじめの一歩 | 1円〜 |
  | 🍀 ファン | 5,000円〜 |
  | 🌟 応援団長 | 20,000円〜 |
  | 👑 パトロン | 50,000円〜 |
  | 💎 伝説の貢ぎ手 | 100,000円〜 |
  - これとは別に、回収が貢いだ金額を**上回ったら**「🎁 恩返し」を、もう1つ付ける。
  - バッジを付ける場所（私の判断）：ホームの主役のカードと推し馬の一覧のカードは「絵文字＋称号」。横に並ぶ小さいカードは、場所がないので**絵文字だけ**。馬カルテは、合計金額の横に「絵文字＋称号」。
  - 名前と区切りは、たたき台（`mitsugi-badge.html`）を作者が異論なく通したもの。
- 見せ方の注意：Play のポリシーで、賭けをあおる見せ方は避ける。「もっと賭けよう」のような文は書かない。応援の気持ちを楽しむ見せ方にする。
- 1件ずつ数える処理は、テストを書ける形（Android に依存しない純粋な Java）にする。今の `Spotlight` / `WinShare` と同じやり方。

## 3. デザインの見直し

作者：「全体的にボタンやデザインがへんだったら見直してモダンな感じにしてほしい」。土台の色は**案1「金色とクリーム」**（作者）。たたき台：`home-modern.html`。

- **色をしぼる**：背景クリーム（`#FFFBF1` あたり）、文字は濃い茶（`#4A3420` あたり）、強調は金・こはく色（`#F5C542`／`#B86A00`）。G1 のカードなどの濃い面は茶色のグラデーション。今の緑（`#4CAF50` など）、青のリンク（`#1565C0`）、オレンジの文字はやめる。
- **赤・オレンジの文字をやめる**：「▶ 11/1(日) 東京11R」「▶ 次走」「天皇賞（秋）」などは、濃い文字の**太字**で目立たせる。
- **ログアウトのボタン**：赤い枠・赤い文字（`fragment_home.xml` の `#D32F2F`）をやめ、控えめなボタンにする。赤は、取り消せない操作（退会など）の確認だけに使う（私の判断）。
- **上の太い緑の帯（アクションバー）**：やめて、背景となじむ細い帯（アイコン＋「推し馬ノート」または画面名）にする。
- **ボタン**：Material 3 の形（角が丸い、目立つボタン＝塗り、控えめ＝枠や文字だけ）に分ける。Google ログインのボタンの「明るい緑に白い文字」をやめて、読みやすくする。
- **下のメニュー**：選んでいるところを丸い色で囲む Material 3 の形。
- **角をもっと丸く**（カード 20dp 前後）。横に並ぶ推し馬のカードは、名前を1行に（長いときは「…」）。
- **土台の部品**：今は `Theme.MaterialComponents.DayNight.DarkActionBar`。Material 3 のテーマに移すのがよい（私の判断。移すか、今の部品のまま色と形だけ変えるかは、作る人が手間とこわれやすさで決めてよい）。
- **色の置き場所**：色が Java（`0xFF…` が約200か所）と XML（`textColor="#…"` が13ファイル）に散らばっている。まとめて名前付きの色（`colors.xml`／テーマの属性）にしてから直す（私の判断）。
- **範囲**：アプリの全画面（ホーム、推し馬、出走表、結果、メモ・予想、馬カルテ、通知の設定、ダイアログ）。ホームが一番大事。
- **ダークモード**：`values-night` があるので、暗い茶色の土台で同じ雰囲気を保つ（私の判断。細かい色は作る人に任せる）。
- 推し馬カードの着せ替えの背景（`CardStyles`、作者がユーザーに選ばせているもの）は、今の色のまま残す。
- 競馬の決まった色（枠番の色 1〜8、G1/G2/G3 の色）は変えない（私の判断。競馬ファンがその色で読んでいるため）。

## 色の変更（2026-10-29、作るとちゅうで作者が決めた）

実機で見た作者が「背景が金だとちらつく」と言い、アプリ全体の色を**やさしい黄緑（案A）**に変えた（たたき台 `home-green.html`）。上の「3. デザインの見直し」の色の値は、次に読みかえる（形・ボタン・赤やオレンジの文字をやめることなどは、そのまま）。
- 背景 `#F8FBF2`、カード `#FFFFFF`、文字 `#2F3B22`、補足 `#56664A`、主色（札・ボタン・帯の面） `#4E7A27`→`#7CB342`、強調・文字のボタン `#4A7A1E`、線 `#DDE8CC`、下のメニュー `#F1F7E7`／選択中 `#DCEDC8`。夜は暗い緑の土台。
- 色の名前は `oshi_primary`／`oshi_accent` など、意味の名前にした。
- G1 の金色のバッジ、主役のカードの「1着！」の金色は残す。
- ウェルカム画面の色を金のままにするか、黄緑にするかは、作者に聞く。

## しないこと

- アプリのアイコン、Play ストアのアイコン・画像は変えない（今は審査中・公開済み）。
- ウェルカム画面の中で、推し馬を登録させない。
- 称号で、カードのアイコンを勝手に変えない。
- 本物の馬券は買わない（記録だけ）。
- Web 版は今回の範囲に入れない（私の判断。必要なら別に）。
